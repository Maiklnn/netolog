# Инструкция: агент визуальных креативов в n8n

Пошаговое руководство: как развернуть агента, запустить его и получить
оформленный результат практики.

---

## 1. Что понадобится

| Компонент | Значение в этом проекте |
|---|---|
| n8n | `http://192.168.56.10:5678/` (проверено на 2.8.4) |
| Сервер n8n | `root@192.168.56.10`, ключ `C:/Users/MIXA/.ssh/unikor` |
| Ollama | `http://10.0.2.2:11434`, модель `deepseek-v4.1-flash:cloud` |
| Папка данных | `/var/lib/n8n/.n8n-files/visual-creatives` |
| Интернет | нужен: картинки генерируют внешние сервисы |

> **Важно.** Ollama должна быть доступна **из сервера n8n**, а не только с вашей
> машины: адрес `10.0.2.2` — это шлюз виртуальной машины, то есть хост-машина.

## 2. Установка за три шага

### Шаг 1. Поднять таймаут Code-узлов

По умолчанию n8n обрывает задачу Code-узла через 5 минут. Запасной генератор
Stable Horde может работать дольше, поэтому таймаут нужно увеличить:

```bash
grep -q '^N8N_RUNNERS_TASK_TIMEOUT=' /etc/n8n/.env || \
  echo 'N8N_RUNNERS_TASK_TIMEOUT=3600' >> /etc/n8n/.env
systemctl restart n8n
systemctl is-active n8n      # должно быть: active
```

### Шаг 2. Положить бриф

Бриф — **внешний файл**, а не константа внутри схемы. Так его можно менять, не
трогая workflow:

```bash
mkdir -p /var/lib/n8n/.n8n-files/visual-creatives
cp brief.json /var/lib/n8n/.n8n-files/visual-creatives/brief.json
```

### Шаг 3. Импортировать workflow

```bash
python tools/n8n-api.py --import workflow-visual-creatives.json
```

Скрипт сам авторизуется в n8n и вернёт `workflowId`. Дальше он же умеет:

```bash
python tools/n8n-api.py --update <workflowId> workflow-visual-creatives.json
python tools/n8n-api.py --run <workflowId>          # запустить
python tools/n8n-api.py --executions <workflowId>   # список выполнений
```

## 3. Запуск и что смотреть

Запустить можно двумя способами.

**Кнопкой.** Открыть workflow в n8n → **Execute workflow**.

**По ссылке (webhook).** Воркфлоу нужно активировать, после этого:

```bash
curl -X POST http://192.168.56.10:5678/webhook/visual-creatives \
     -H 'Content-Type: application/json' \
     -d '{"overrides": {"fix_threshold": 2}}'
```

В теле можно передать `brief_path` (другой бриф) и `overrides` — настройки,
которые перекрывают бриф: `fix_threshold`, `vision_model`, `data_dir`.
Например, `{"overrides": {"fix_threshold": 0}}` включает ветку правки почти для
всех креативов — удобно, чтобы показать доработку.

Ответ webhook — короткая сводка:

```json
{
  "status": "ok",
  "variants": 4,
  "fixed": 0,
  "files": ["V1-a1.webp", "V2-a1.webp", "V3-a1.webp", "V4-a1.webp"],
  "difference_source": "vision-модель",
  "checks_failed": []
}
```

> **Проверено на живой схеме.** Вызов с телом `{"overrides": {"fix_threshold": 4}}`
> вернул `HTTP 200` за 13,6 минуты. В ответе `"fixed": 0`, но при этом в
> `checks_failed` стоят `V3: 3 «нет»` и `V4: 3 «нет»` — то есть переопределение
> дошло до узла `Оценка по чек-листу`: при штатном пороге 2 эти креативы ушли бы
> на правку, а с порогом 4 — нет. Ответ целиком сохранён в
> `result/прогоны/webhook-ответ-89.json`.

### Результаты на диске сервера

```bash
ls -la /var/lib/n8n/.n8n-files/visual-creatives/images/   # сами креативы
cat /var/lib/n8n/.n8n-files/visual-creatives/registry.md  # читаемый отчёт
cat /var/lib/n8n/.n8n-files/visual-creatives/registry.csv # таблица для Excel
```

`registry.json` — тот же отчёт целиком, вместе с оценками vision-модели; из него
заполняется шаблон задания.

## 4. Как работает вариативность

Требование задания — «для одного из брифов изменить **только один** параметр».
В брифе это вариант **V4**: он отличается от V1 исключительно стилем
(минимализм → яркий, контрастный).

Сделано это не уговорами модели, а кодом узла `Собрать промты`:

1. LLM-агент для альтернативы возвращает не полный промт, а пару
   `style_swap: {from, to}` — какой фрагмент на какой менять.
2. Узел берёт **готовый промт базового варианта V1** и заменяет в нём ровно
   этот фрагмент — всё остальное остаётся буквально тем же текстом.
3. Сид копируется от базового варианта принудительно (`t.seed = base.seed`),
   поэтому кадр остаётся тем же.
4. Если фрагмент в промте не нашёлся, узел честно помечает результат как
   запасной промт и пишет предупреждение в реестр — молча подменять нельзя.

Дополнительно в брифе зафиксировано поле `unchanged_parameters`: сегмент ЦА,
площадка, размер, композиция, фокус, акцент, сюжет и сид — без изменений.

## 5. Проверка по чек-листу и правка

После каждой генерации vision-модель оценивает картинку по четырём пунктам
шаблона:

1. соответствие брифу, бренду, площадке;
2. релевантность ЦА;
3. отсутствие запрещённых элементов;
4. техническое качество.

Ответ модели — строгий JSON с четырьмя «да/нет», комментарием и предложением по
улучшению. Узел `Оценка по чек-листу` считает количество «нет» и по условию
задания отправляет на правку **только те креативы, где «нет» больше двух**
(порог `fix_threshold`, по умолчанию 2 — то есть 3 или 4 «нет»).

Правка — не новая случайная картинка: узел `Правка промта` дописывает в промт
уточнения по проваленным пунктам и сохраняет прежние значения в поля
`previous_*`. Максимум две попытки.

**Сид при правке не меняется.** Раньше он менялся (`seed + 1000 × попытка`), и это
ломало главное требование задания: альтернатива V4 — это V1 с изменённым ровно
одним параметром, сид для неё копируется от V1 принудительно. Как только правка
уводила сид, пара V1/V4 расходилась по кадру, и «чем отличается результат»
описывал уже две разные сцены, а не разницу стилей (в прогоне 87 V1 попал в
правку, V4 — нет). Теперь меняется только текст промта: кадр остаётся тем же.

**Побеждает попытка с меньшим числом «нет», а не более поздняя.** Правка может
сделать хуже: в прогоне 87 у V1 первая попытка дала 3 «нет», а «исправленная» —
4. Реестр теперь оставляет лучшую попытку (при равенстве — первую, чтобы сохранить
исходный кадр) и пишет в комментарий: «Правка выполнена, но результат оказался
хуже (4 «нет» против 3) — оставлен исходный вариант». В таблице это видно по
столбцам «Попыток» и «Правка выполнена».

## 6. Заполнение шаблона задания

```bash
python tools/fill-template.py
```

Скрипт берёт исходный шаблон из `source/`, результаты из `result/registry.json`
и картинки из `creatives/`, после чего пишет
`result/Шаблон_для_выполнения_задания_заполненный.xlsx`:

* лист «Бриф», ячейка **B7** — текст брифа;
* лист «Генерация», блоки строк **3–6, 7–10, 11–14, 15–18** — варианты V1, V2,
  V3 и альтернатива V4: площадка, ЦА, параметры генерации, файл креатива,
  ссылка на альтернативу, какой параметр изменён, чем отличается результат;
* столбец **I** — ответы чек-листа («да/нет») построчно,
  формулировки пунктов в столбце H уже есть в шаблоне;
* картинки вставлены прямо в ячейки столбцов D и E как превью.

Затем файл нужно загрузить на облачный диск и вставить ссылку в поле
«Ссылка на решение» — это действие выполняется вручную, из-под пользователя.

## 7. Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| Все креативы одинаковые, в реестре `prompt_source: fallback` | LLM-агент вернул не JSON | включить у узла `Ollama Chat Model` опцию `Output Format = JSON`: без неё модель-рассуждалка пишет прозу вместо объекта |
| `prompt_source: fallback`, но в узле `Агент: промт-инженер` видно готовый JSON с вариантами | модель печатает размышление, затем JSON, и на склейке теряются первые символы объекта (`…Output JSON only.ants":[…`) — прямой `JSON.parse` на таком тексте падает | узел `Собрать промты` должен разбирать ответ в три ступени (см. `README.md`, находка 3); проверка — `node tools/test-extract-json.js`. В реестре причина видна как `agent_json_ok: false` при `agent_answer_chars` в десятки тысяч |
| В папке `images/` один файл `undefined.webp` вместо четырёх | у элементов не было поля `file_name`, и все варианты писались по одному пути | поле задаётся в `03-build-prompts.js`; проверьте, что узел не переписан старой версией |
| `Ни один генератор не отдал изображение` | у HF-спейсов кончилась квота ZeroGPU, Stable Horde не успел за 35 минут | повторить запуск: очередь Horde дышит, а квота HF со временем восстанавливается |
| Долгое ожидание на узле `Генерация FLUX` | это Stable Horde: очередь анонимного клиента тем длиннее, чем крупнее картинка | ничего не делать: через 3 минуты узел сам досылает лёгкий размер |
| Прогон висит, а по API у него пустой `runData` | у workflow выключен `saveExecutionProgress`, n8n не пишет прогресс узлов до конца | включить флаг в настройках workflow; тогда прогресс покажет `python tools/watch-exec.py <id>` |
| Узел `Генерация FLUX` ждёт все 35 минут, хотя лёгкий размер должен был прийти | Stable Horde ответил `429`: анонимному клиенту разрешён примерно один запрос в секунду, а узел слал пачку опросов подряд | в узле есть паузы `HORDE_GAP_MS` / `HORDE_POLL_GAP_MS` и повтор отправки; если правите код — паузы не убирайте |
| В реестре у креатива `size_downgraded: true` | тяжёлый размер не дождался воркера, картинка сделана лёгким | нормальное поведение; в часы нагрузки Stable Horde закрывает запросы 1024×1024 порогом «заслуг» (`403 KudosUpfront`), тогда лёгкий запас и есть рабочий путь — полный размер получится, если повторить запуск в спокойное время |
| У 512-пиксельных креативов вместо фотографии абстрактная «векторная» картинка | модель SDXL 1.0 рассчитана на 1024 и на маленьком размере уходит в стилизацию | не ждать лёгкий размер на тяжёлой модели: узел досылает лёгкий запас на 512-нативной модели, а тяжёлую задачу продолжает опрашивать |
| Лёгкий запас вышел «не по сюжету»: в кадре нет героя, композиция потеряна | в списке моделей лёгкого эшелона стоит base-модель `stable_diffusion` — она держит сцену хуже финетюнов | список моделей задаётся в `04-generate.js`; там должны быть финетюны (`AbsoluteReality`, `Realistic Vision`, `Deliberate`), подбор — `python tools/horde-model-pick.py` |
| В строке параметров реестра `запреты` указан «английский список из брифа», хотя агент писал список по-русски | генератор не понимает русский текст: русский `negative` для него пустой | это и есть защита, а не ошибка; если нужно своё, требуйте от агента английского списка в `negative` |
| После правки креатив стал хуже, чем был | в промт попали русские уточнения (старый узел правки собирал их из русских полей брифа) | узел `Правка промта` должен брать английские двойники полей (`style_en`, `focus_en`); в реестре об этом пишет `prompt_language_fixed` |
| В реестре у правки есть `prompt_language_fixed: true` | кириллица всё-таки попала в промт и была вырезана уже на выходе | проверьте, что в брифе заполнены английские поля |
| `illegal base64 data at input byte 10` | base64 собирали из `binary.data.data`, а там ссылка файлового режима | читать байты только через `helpers.getBinaryDataBuffer` |
| Картинка сохранилась «битой» | её скачивал Code-узел через `helpers.httpRequest` | качать только узлом HTTP Request (`responseFormat: file`) или отдавать base64 в узел `Картинка из base64` |
| Code-узел обрывается на `Генерация FLUX` | не поднят `N8N_RUNNERS_TASK_TIMEOUT` | см. шаг 1 установки |
| Vision не отвечает | Ollama недоступна с сервера n8n или нет модели | проверить `curl http://10.0.2.2:11434/api/tags` с сервера n8n |

Диагностика бинарных данных, если понадобится повторить:

```bash
python tools/watch-exec.py <id>          # какие узлы прогона уже отработали и сколько шли
python tools/exec-state.py <id>          # снимок: на каком узле прогон стоит прямо сейчас
python tools/inspect-exec.py <id>        # что вернул конкретный узел завершённого прогона
python tools/node-dump.py <id> <узел> id prompt_source   # только нужные поля узла
node tools/test-extract-json.js          # разбор ответа LLM-агента на боевых ответах
python tools/probe-binary-roundtrip.py   # проверяет Code-узел: буфер и сборка файла
python tools/probe-binary.py             # проверяет, как хранятся бинарники в этом n8n
python tools/generator-probe.py          # отвечают ли спейсы Hugging Face
python tools/horde-size-test.py          # сколько ждать очередь Stable Horde на боевых размерах
python tools/horde-queue-probe.py        # очередь и порог «заслуг» на разных моделях
python tools/horde-model-pick.py         # сравнить модели лёгкого эшелона на одном промте
```

## 8. Безопасность

* Пароль администратора n8n лежит открытым текстом в `tools/n8n-api.py`.
  Перед передачей проекта куда-либо перенесите его в переменную окружения
  (`N8N_PASSWORD`) или удалите файл.
* В брифе намеренно используется **вымышленный бренд LinguaUp**: генераторы не
  должны воспроизводить реальные логотипы, и это же требование заказчика
  зафиксировано в списке запрещённых элементов.
