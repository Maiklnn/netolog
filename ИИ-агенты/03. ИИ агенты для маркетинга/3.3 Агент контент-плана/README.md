# Практика: агент контент-плана — загородный клуб «Тихий лес»

ИИ-агент контент-планирования, собранный в **n8n 2.8.4** (self-hosted) с локальной
моделью через **Ollama**. Агент раз в неделю собирает контент-план на 7 дней для
загородного клуба отдыха «Тихий лес», пишет по нему готовые материалы (два поста
в двух версиях и сценарий рилса), проверяет результат 22 автоматическими
проверками и складывает расписание публикаций для демо-среды.

Задание выполнено по шаблону «Практика: агент контент-плана»: разделы 1–6 этого
файла повторяют структуру шаблона.

## 1. Кейс и исходные данные

### 1.1. Бренд и продукт

**Бренд:** загородный клуб отдыха «Тихий лес».

«Тихий лес» — загородный клуб отдыха, специализирующийся на форматах восстановления, цифрового детокса и спокойного отдыха вдали от города. Основная концепция бренда — помочь гостям снизить стресс, восстановить энергию и перезагрузиться за счёт природы, тишины и программ отдыха без цифровой перегрузки.

### 1.2. Цель бизнеса

**Основная цель:** привлечение новых гостей через контент-маркетинг и формирование образа клуба как места для восстановления, отдыха и эмоциональной разгрузки.

**Дополнительные цели:**

- повышение узнаваемости бренда
- рост бронирований
- формирование доверия через контент

### 1.3. Целевая аудитория

**Основная аудитория:** предприниматели, руководители, специалисты с высокой нагрузкой, возраст 30–50 лет.

### 1.4. Боли и потребности

**Основные боли аудитории:**

- постоянный стресс и эмоциональная перегрузка
- отсутствие качественного отдыха
- невозможность «отключиться» от работы
- усталость от информационного шума
- выгорание

**Ключевые потребности аудитории:**

- восстановление энергии
- тишина и уединение
- перезагрузка без гаджетов
- качественный отдых на природе
- время для себя и семьи

### 1.5. Позиционирование и тон коммуникации

**Позиционирование:** «Тихий лес» — это пространство цифрового детокса и восстановления, где человек может полностью отключиться от рабочего ритма и вернуть ресурсное состояние.

**Тон контента:** экспертный; спокойный; доверительный; без агрессивных продаж; с акцентом на восстановление и ценность отдыха.

## 2. Описание ИИ-агента контент-планирования

**Платформа:** n8n (self-hosted) + локальная LLM через Ollama.

### 2.1. Ссылка на агента

Агент собран в n8n, а не в Yandex AI Studio, поэтому вместо ссылки на студию — рабочая ссылка на workflow:

- Запуск по ссылке: `GET http://192.168.56.10:5678/webhook/content-plan`
- Интерфейс n8n: http://192.168.56.10:5678/ (workflow «Агент контент-плана: загородный клуб „Тихий лес“»)

### 2.2. Роль и цель агента

**Роль:** Агент действует как senior контент-маркетолог с опытом 10+ лет в сфере lifestyle и premium-отдыха, специализирующийся на создании контент-стратегий для брендов в сфере wellness и hospitality.

**Цель агента:** собрать контент-план на неделю для клуба «Тихий лес», который привлекает новых гостей, снижает тревогу аудитории вокруг перегрузки и усиливает образ места восстановления, — и подготовить по нему готовые к согласованию материалы.

### 2.3. Входные данные для агента

| Источник | Что внутри | Зачем агенту |
|---|---|---|
| `brand-brief.md` — бриф бренда | продукт, цель бизнеса, ЦА, боли и потребности, позиционирование, тон | чтобы план говорил на языке бренда и не выдумывал факты о клубе |
| `content-rules.md` — правила контента | периодичность, баланс задач, список рубрик, форматы, требования площадок, запрещённые формулировки, лестница статусов | это рамки, которые задал пользователь: агент действует внутри них, а не придумывает свои приоритеты |
| `content-log.csv` — журнал прошлых публикаций | 18 публикаций с площадкой, рубрикой, задачей, форматом и метриками (просмотры, реакции, комментарии, сохранения, ER) | поведенческий источник: агент видит, что сработало, а что нет, и что уже было в последние две недели |
| Календарь недели | даты с ближайшего понедельника | чтобы план лёг на реальные даты |

### 2.4. Формат результата агента

Агент отвечает тремя связанными блоками: (1) таблица контент-плана на 7 дней — день и дата, рубрика, тема, формат, площадка, цель; (2) готовые тексты — два поста в двух версиях каждый (Telegram и ВКонтакте) и сценарий короткого видео по сценам; (3) таблица расписания для демо-среды со статусами и точками контроля. Дополнительно агент сам прогоняет 22 проверки качества и показывает чек-лист самооценки.

### 2.5. Структура агента

Агент собран в n8n как один workflow из **26 узлов**. Ветка «стратегия → генерация»
дополнена двумя контурами контроля качества, которые могут вернуть работу назад:

```
ТРИГГЕРЫ
  Расписание (еженедельно, Чт 10:00) ─┐
  Запуск вручную (кнопка)            ─┼─► 1. Бриф бренда (MD) ───► 1. Бриф бренда (текст)
  Запуск по ссылке (Webhook GET)     ─┘   2. Правила контента (MD) ► 2. Правила (текст)
                                          3. Журнал публикаций (CSV) ► 3. Журнал (текст)
                                                    │
                                                    ▼
  ПОДГОТОВКА   Подготовка входных данных
               календарь недели, статистика журнала (ER по рубрикам, задачам,
               форматам), список тем последних 14 дней, готовый пакет для стратега
                                                    │
                                                    ▼
  СТРАТЕГИЯ    Контент-стратег (LLM)  ◄── Ollama Chat Model (стратег)
               системный промпт стратега: план на 7 дней строго по правилам
                                                    │
                                                    ▼
               Разбор контент-плана
               достаёт JSON, нормализует план и прогоняет 12 проверок
                                                    │
                                                    ▼
  КОНТРОЛЬ 1   План забракован?  ── да ──► назад к «Контент-стратег (LLM)» (не больше 2 попыток)
                                    └─ нет ─┐
                                            ▼
  ГЕНЕРАЦИЯ    Копирайтер (LLM)  ◄── Ollama Chat Model (копирайтер)
               два поста (Telegram + ВКонтакте) и сценарий рилса по маркерам
                                            │
                                            ▼
               Разбор контента
               режет ответ по маркерам, считает символы, ищет запрещённые
               формулировки — 10 проверок
                                            │
                                            ▼
  КОНТРОЛЬ 2   Материалы забракованы? ── да ──► назад к «Копирайтер (LLM)» (не больше 2 попыток)
                                         └─ нет ─┐
                                                 ▼
  ВЫХОД        Самопроверка качества  — сводит 22 проверки в чек-лист из 6 вопросов
                    │
                    ▼
               Сборка демо-публикации — расписание на 14 строк, статус не выше «на проверке»
                    │
                    ▼
               Сборка итогового документа — документ по структуре шаблона ДЗ
                    │
                    ▼
               Подготовка файла (Markdown) ──► Сохранить контент-план на диск
               Подготовка файла (CSV)      ──► Сохранить расписание демо-среды
                    │
                    ▼
               Показать результат — ответ webhook и список файлов
```

**Ключевые узлы:**

| Узел | Что делает |
|---|---|
| Подготовка входных данных | считает календарь недели по ближайшему понедельнику, ER по рубрикам/задачам/форматам из журнала и собирает текстовый пакет для стратега |
| Контент-стратег (LLM) | строит план на 7 дней: рубрика, задача, тема, формат, площадка, цель и идея по каждому дню |
| Разбор контент-плана | извлекает JSON из ответа модели и проверяет план 12 правилами заказчика; формирует задание копирайтеру |
| План забракован? | возвращает забракованный план стратегу на пересборку |
| Копирайтер (LLM) | пишет два поста (в двух версиях каждый) и сценарий рилса по маркерам |
| Разбор контента | разбирает материалы по маркерам и проверяет их 10 правилами |
| Материалы забракованы? | возвращает забракованные материалы копирайтеру на переписывание |
| Самопроверка качества | сводит все 22 проверки и отвечает на 6 вопросов чек-листа шаблона |
| Сборка демо-публикации | делает таблицу расписания: 14 строк, статус не выше «на проверке» |
| Сборка итогового документа | собирает документ по структуре шаблона ДЗ |

### 2.6. Системные промпты

Промпты лежат в репозитории отдельными файлами и попадают в workflow как есть:

| Файл | Кому |
|---|---|
| `tools/02-strategist-prompt.md` | системный промпт контент-стратега |
| `tools/04-copywriter-prompt.md` | системный промпт копирайтера |

Оба промпта решают одну и ту же проблему: модель — «рассуждающая», она склонна
проговаривать ход мысли и печатать черновики. Поэтому в промпте заданы жёсткие
маркеры структуры ответа (`###ПЛАН### … ###КОНЕЦ###`, `###ПОСТ_1###`,
`###КОНЕЦ_ПОСТА_1###`, `###РИЛС###` и т. д.), прямой запрет на рассуждения и
черновики, а лимиты площадок продублированы в последнем сообщении — короткое
напоминание в конце работает надёжнее, чем абзац в системном промпте.

Отдельно в промпте копирайтера перечислены запрещённые формулировки (гарантии
результата, срочность, медицинские обещания, сравнения с конкурентами) — не
потому, что модель их не знает, а потому что проверка их ловит механически,
и дешевле не допустить их, чем чинить.

### 2.7. Проверки качества и повторная генерация

Проверки — не декорация: по их итогам агент либо идёт дальше, либо возвращает
работу на пересборку. Правило одно: **если брак, а попытка первая — возвращаем;
если брак, а попытка вторая — идём дальше и честно пишем об этом в отчёте.**

Номер попытки берётся из системной переменной `$runIndex` — n8n сам ведёт счётчик
прогонов узла внутри цикла. Это оказалось важным: попытка считать прогоны через
`$('Узел').all().length` даёт накопление данных, из-за которого цикл не сходится.

Проверка не проходит по существу, а не по оформлению: если модель забыла
декоративный маркер, но текст на месте и разбирается — материал считается рабочим,
и в отчёте появляется примечание о том, что маркер не найден. Так же устроен и
разбор плана: если JSON не разобрался с первого раза, сценарий не падает,
а отправляет стратегу задание с текстом неудачного ответа.

Полный список 22 проверок — в разделе 8.

### 2.9. Периодичность запуска

Выбрано: **1 раз в неделю**, дополнительно — вручную по кнопке и по ссылке.

Узел «Расписание (еженедельно, Чт 10:00)» запускает агента каждый четверг в 10:00
по времени сервера: к этому моменту известны результаты публикаций недели, и у редактора остаётся
время до понедельника, чтобы проверить план и материалы. Недельный шаг выбран
потому, что горизонт планирования в правилах контента — одна неделя, а журнал
публикаций пополняется один раз в неделю; ежедневный запуск не дал бы новых
данных, но каждый раз тратил бы два обращения к модели.

## 3. Контент-план по кейсу «Тихий лес»


### 3.1. Период

Период контент-плана: **2026-10-12 — 2026-10-18** (7 дней, по одной публикации в день; каждая выходит в двух версиях — Telegram и ВКонтакте).

### 3.2. Таблица контент-плана

| День / дата | Рубрика | Тема поста / материала | Формат | Площадка | Цель / комментарий |
|---|---|---|---|---|---|
| 1. 2026-10-12 (понедельник) | Тишина как ресурс | Что происходит с вниманием, когда день расписан по минутам | пост | Telegram + ВКонтакте | Задать спокойный экспертный тон недели и объяснить природу перегрузки, с которой приходит аудитория. |
| 2. 2026-10-13 (вторник) | Практики восстановления | Три вопроса, которые возвращают в тело после рабочего дня | карточка-практика | Telegram + ВКонтакте | Дать аудитории применимый инструмент и повысить сохранения публикаций. |
| 3. 2026-10-14 (среда) | Как здесь устроено | Один день в «Тихом лесу»: как выглядит отдых без телефона | короткое видео | Telegram + ВКонтакте | Показать пространство и ритм клуба так, чтобы у зрителя сложился образ будущей поездки. |
| 4. 2026-10-15 (четверг) | Истории гостей | «Я впервые за год дочитал книгу до конца» | пост | Telegram + ВКонтакте | Снять сомнение «а получится ли у меня отключиться» через опыт человека из целевой аудитории. |
| 5. 2026-10-16 (пятница) | Тишина как ресурс | Тишина как навык: почему к ней нужно привыкать постепенно | карусель | Telegram + ВКонтакте | Снять внутреннее сопротивление перед поездкой и объяснить, что тишина — осваиваемое состояние, а не испытание. |
| 6. 2026-10-17 (суббота) | Как здесь устроено | Как собрать свой заезд: три сценария отдыха в «Тихом лесу» | подборка | Telegram + ВКонтакте | Мягко перевести интерес в бронирование, показав варианты под разный ритм и разную нагрузку. |
| 7. 2026-10-18 (воскресенье) | Тишина как ресурс | Что для вас признак настоящего отдыха: тишина, сон или пустая голова? | опрос | Telegram + ВКонтакте | Собрать диалог и данные о том, как аудитория сама описывает восстановление. |

**Как распределились задачи недели:** Задачи: объяснить — 2 (дни 1 и 5), практика — 1 (день 2), показать продукт — 1 (день 3), кейс — 1 (день 4), подвести к бронированию — 1 (день 6), вовлечь — 1 (день 7); итого 7, повторов подряд нет. Продающая публикация стоит шестой, не первой, и не соседствует с однотипным контентом: перед ней объясняющая карусель, после — вовлекающий опрос. Рубрики: «Тишина как ресурс» — дни 1, 5, 7; «Как здесь устроено» — дни 3, 6; «Истории гостей» — день 4; «Практики восстановления» — день 2; использованы все четыре. Форматы идут без повторов два дня подряд: пост, карточка-практика, короткое видео, пост, карусель, подборка, опрос. Все темы — новые углы, не пересекаются с публикациями за последние 14 дней; формулировки без гарантий, срочности, сравнений и медицинских обещаний.

**Выводы из журнала публикаций, повлиявшие на план:**

1. Лучший отклик дают объясняющие публикации в рубрике «Тишина как ресурс»: ER 7.2% по задаче и 6.9% по рубрике, поэтому они открывают неделю и повторяются в середине.
2. Максимум комментариев и сохранений приносят «Истории гостей» и практики (27.3 и 31.6 комментария, до 44 сохранений), поэтому кейс и карточка-практика стали ядром вовлечения, а не развлекательным дополнением.
3. Слабейшие результаты у опросов и прямой продажи (ER 4.9% и 4.7%), но опросы дают много комментариев — поэтому продающий пост один и не первый, а опрос один и стоит в конце недели.

## 5. Сценарий публикации в демо-среде

### 5.1. Периодичность и порядок выхода

**Периодичность публикаций:** 7 публикаций в неделю — по одной в день, без пропусков. Каждая публикация выходит в двух версиях: Telegram в 09:00, ВКонтакте в 18:30. Ритм задан заранее контент-планом на неделю 2026-10-12 — 2026-10-18.

**Порядок выхода материалов:**

1. Агент запускается по расписанию раз в неделю (или вручную) и собирает план на ближайшую неделю, начиная с понедельника.
2. Порядок публикаций подчинён логике прогрева: сначала объясняющий контент о перегрузке и восстановлении, затем знакомство с пространством и продуктом, кейс гостя, вовлекающий вопрос и практика. Продающая публикация — только после того, как аудитория получила полезное: она занимает 6-й день недели.
3. Материалы попадают в демо-среду — таблицу расписания. Запись создаётся на каждую версию публикации, всего 14 строк на неделю.
4. Каждая строка проходит лестницу статусов: идея → черновик → на проверке → готово к демо → одобрено. Агент доводит статус максимум до «на проверке» и никогда не публикует сам.
5. После одобрения редактором запись переводится в «готово к демо», и только затем материал уходит в отложенный постинг площадок.
6. Результаты недели (просмотры, реакции, комментарии, сохранения, ER) возвращаются в журнал публикаций — следующий запуск агента учитывает их при выборе тем и форматов.

она срабатывала (попытки 2/2) и возвращала результат к 22/22 — это видно в
истории запусков.

## 8. Автоматическая самопроверка агента

Узел «Самопроверка качества» прогоняет результат по 22 механическим проверкам
и сводит их в шесть вопросов чек-листа шаблона. Последний прогон: **22 из 22**.

**Проверки контент-плана (12):**

| № | Проверка |
|---|---|
| 1 | Ответ модели разобран в структуру контент-плана |
| 2 | В плане 7 публикаций на 7 дней |
| 3 | Даты совпадают с календарём недели |
| 4 | Задачи распределены по правилу: «объяснить» — дважды, остальные по одному разу |
| 5 | Нет посторонних рубрик и задач |
| 6 | Использованы все четыре рубрики |
| 7 | Форматы только из разрешённого списка |
| 8 | Один формат не идёт два дня подряд |
| 9 | Продающая публикация не первая в неделе |
| 10 | Темы не повторяют публикации последних двух недель |
| 11 | Для проработки выбраны 3 темы: 2 поста и рилс |
| 12 | Выбранные темы есть в плане |

**Проверки материалов (10):**

| № | Проверка |
|---|---|
| 13 | Ответ модели разобран в три материала: два поста и сценарий рилса |
| 14 | Оба поста разобраны и содержат обе версии |
| 15 | Пост для Telegram укладывается в 900 символов |
| 16 | Пост для ВКонтакте укладывается в 1400 символов |
| 17 | Версии для Telegram и ВКонтакте различаются, а не скопированы |
| 18 | ВКонтакте: не больше 3 хэштегов и есть вопрос к читателю |
| 19 | В Telegram нет хэштегов |
| 20 | Нет запрещённых формулировок |
| 21 | Сценарий рилса содержит хук, основную часть и финальную мысль |
| 22 | В рилсе нет запрещённых формулировок |

Проверки 15–19 — это ровно те требования площадок, которые заданы в правилах
контента, и именно они нарушаются чаще всего, поэтому лимиты продублированы
в последнем сообщении копирайтеру.

## 9. Демо-среда: как выглядит результат

Агент записывает расписание в CSV — по строке на каждую версию публикации,
14 строк на неделю. Первые строки файла `result/demo-schedule-2026-10-12.csv`:

```csv
Дата;Время;День недели;Рубрика;Задача;Тема;Формат;Площадка;Статус;Материал;Проверяющий
2026-10-12;09:00;понедельник;Тишина как ресурс;объяснить;Что происходит с вниманием, когда день расписан по минутам;пост;Telegram;на проверке;готов;контент-редактор (человек)
2026-10-12;18:30;понедельник;Тишина как ресурс;объяснить;Что происходит с вниманием, когда день расписан по минутам;пост;ВКонтакте;на проверке;готов;контент-редактор (человек)
```

Лестница статусов: `идея → черновик → на проверке → готово к демо → одобрено`.
Агент останавливается на статусе **«на проверке»** — ни одна публикация не уходит
на площадку без человека.
