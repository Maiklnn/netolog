## О задаче

Вы — ИИ-инженер сервисной компании, которая получает сотни обращений в поддержку в сутки.
Нужно автоматически маршрутизировать заявки по категориям, чтобы ускорить их обработку.

**Датасет:** [IT Service Ticket Classification Dataset](https://www.kaggle.com/datasets/adisongoh/it-service-ticket-classification-dataset)
(`data/all_tickets_processed_improved_v3.csv`).

| Параметр | Значение |
|---|---|
| Строк | 47 837 (после очистки пустых — 47 835) |
| Колонки | `Document` (текст), `Topic_group` (метка) |
| Классов | 8 |
| Пропуски / дубликаты | нет |
| Длина обращения | в среднем 44 слова, медиана 26, максимум 981 |
| Дисбаланс | Hardware 28,5 % против Administrative rights 3,7 % (≈7,7×) |
| Train / test | 38 268 / 9 567 (80/20, `stratify=y`) |

Категории: `Hardware`, `HR Support`, `Access`, `Miscellaneous`, `Storage`, `Purchase`,
`Internal Project`, `Administrative rights`.

## Результаты

Тестовая выборка — 9 567 обращений, метрика отбора — F1-macro (из-за дисбаланса классов).

| Модель | Accuracy | Precision macro | Recall macro | F1-macro | F1-weighted | Время обучения |
|---|---|---|---|---|---|---|
| **LinearSVC** | **0,8562** | **0,8535** | **0,8609** | **0,8567** | **0,8561** | 2,3 с |
| LogisticRegression | 0,8544 | 0,8492 | 0,8628 | 0,8554 | 0,8545 | 8,4 с |
| PyTorch MLP | 0,8358 | 0,8428 | 0,8292 | 0,8356 | 0,8361 | 19,9 с |
| ComplementNB | 0,8163 | 0,8200 | 0,8025 | 0,8074 | 0,8154 | 1,6 с |

Все модели обучались в едином MLflow-эксперименте `ticket-classification`
(хранилище — `mlflow.db` + `mlruns/`), у каждого run залогированы параметры,
метрики, `classification_report` и матрица ошибок.

### Лучшая модель — LinearSVC

- Наивысшие accuracy и F1-macro; отрыв от логистической регрессии мал (0,0013 F1-macro,
  ≈15 объектов из 9 567), но LinearSVC быстрее в 4 раза и лучше почти на всех классах.
- TF-IDF по 50 000 признакам (уни- и биграммы, `min_df=2`, `sublinear_tf=True`) —
  почти линейно разделимая задача; SVM с `class_weight='balanced'` уверенно отделяет
  редкие классы.

### Анализ ошибок (LinearSVC, 1 376 ошибок из 9 567)

| Класс | Precision | Recall | F1 | Доля ошибок |
|---|---|---|---|---|
| Administrative rights | 0,794 | 0,767 | 0,780 | 23,3 % |
| Miscellaneous | 0,809 | 0,850 | 0,829 | 15,0 % |
| Hardware | 0,853 | 0,826 | 0,839 | 17,4 % |
| Internal Project | 0,812 | 0,894 | 0,851 | 10,6 % |
| HR Support | 0,872 | 0,853 | 0,862 | 14,8 % |
| Storage | 0,866 | 0,899 | 0,882 | 10,1 % |
| Access | 0,886 | 0,909 | 0,897 | 9,1 % |
| Purchase | 0,936 | 0,891 | 0,913 | 11,0 % |

Самые частые путаницы: `HR Support → Hardware` (141), `Hardware → HR Support` (139),
`Hardware → Miscellaneous` (124), `HR Support → Miscellaneous` (88).

Причина — общая служебная лексика (`access`, `account`, `rights`, `please`) и шаблонные
формулировки; хуже всего даётся самый редкий класс `Administrative rights`.
MLP ошибается по тем же причинам, но глубже: F1 этого класса падает до 0,7206.
Сеть к тому же переобучается — train accuracy 0,964 против test 0,836, а test loss
после 2-й эпохи начинает расти.

### Выводы

- Решение пригодно как **первая линия маршрутизации** с порогом уверенности и ручной
  проверкой сомнительных заявок, но не как единственный классификатор: ≈14 % обращений
  уйдут не в тот отдел.
- Ограничения: дисбаланс классов, сильная анонимизация текстов (`icon`, обрывки фраз),
  TF-IDF не учитывает контекст и синонимы, датасет статичный и англоязычный.
- Направления улучшения: больше данных по редким классам, подбор гиперпараметров через
  кросс-валидацию, контекстные эмбеддинги (BERT/`sentence-transformers`), калибровка порога,
  мониторинг дрейфа и регулярное дообучение.

## Как запустить

```bash
# 1. Виртуальное окружение и зависимости
python -m venv .venv
# Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 2. Данные
#    файл data/all_tickets_processed_improved_v3.csv уже в репозитории;
#    при необходимости скачать заново:
#    https://www.kaggle.com/datasets/adisongoh/it-service-ticket-classification-dataset

# 3. Ноутбук
jupyter notebook notebook.ipynb
# Kernel -> Restart and Run All

# 4. MLflow UI (сравнение run'ов)
mlflow ui --backend-store-uri sqlite:///mlflow.db
```

Ноутбук полностью воспроизводим: все шаги выполняются от начала до конца без ошибок
на CPU примерно за 3 минуты (из них предобработка текста — ~5 секунд, обучение трёх
классических моделей — ~12 секунд, обучение MLP — ~20 секунд).
