## Цель

Это задание поможет закрепить навыки построения воспроизводимых ML-пайплайнов. Нужно пройти полный цикл:
от анализа данных до автоматизации и логирования экспериментов — так, как это делают в production-командах.

Без pipeline обучение модели превращается в набор разрозненных скриптов, которые невозможно воспроизвести.

## Чему научитесь

- собирать полноценный ML-pipeline для задачи многоклассовой классификации на реальных данных;
- проводить сравнение нескольких моделей и оценивать их качество с помощью кросс-валидации;
- логировать параметры, метрики и артефакты моделей в MLflow;
- делать обоснованные выводы о качестве моделей на основе залогированных экспериментов;
- понимать, как оркестрировать pipeline в продакшене (пример на Apache Airflow).

## Описание задания

В распоряжении датасет продаж кофе `Coffe_sales.csv` с информацией о транзакциях в кофейне:
дата и время покупки, тип оплаты, сумма чека, название напитка и производные временные признаки.

Необходимо построить воспроизводимый ML-pipeline для задачи **многоклассовой классификации**:
прогнозирование типа кофе (`coffee_name`), который закажет клиент, на основе времени покупки,
дня недели, месяца и суммы чека.

### Обязательные шаги

1. Загрузите данные, проведите первичный анализ (EDA) и сформулируйте выводы о структуре данных.
2. Выполните генерацию признаков (feature engineering) из временных колонок.
3. Постройте бейзлайн-модель и зафиксируйте её метрики.
4. Обучите минимум три различные модели (например, логистическую регрессию, случайный лес, градиентный бустинг),
   оцените их качество кросс-валидацией.
5. Для лучшей модели выполните подбор гиперпараметров (например, с помощью Optuna).
6. Залогируйте все эксперименты (бейзлайн, сравнение моделей, финальная модель) в MLflow:
   параметры, метрики accuracy и f1-macro, а также сами модели.
7. Запустите MLflow UI, сделайте скриншот сравнения экспериментов и приложите его к решению.

Дополнительно: напишите пример DAG для Apache Airflow, который автоматизирует pipeline.

## Инструкция к выполнению

**Шаг 1. Подготовка окружения**

- Создайте виртуальное окружение и установите библиотеки:
  `pip install pandas scikit-learn mlflow optuna matplotlib seaborn`
- Убедитесь, что файл `Coffe_sales.csv` находится в рабочей директории.

**Шаг 2. EDA и подготовка данных**

- Откройте ноутбук `coffee_ml_pipeline.ipynb` (или создайте свой).
- Загрузите данные, изучите типы колонок, проверьте пропуски и распределение целевой переменной `coffee_name`.
- Приведите `Date` к типу `datetime`.

**Шаг 3. Feature Engineering**

- Создайте новые признаки из даты: день месяца, номер недели в году, признак выходного дня.
- Сформируйте матрицу признаков `X` и целевой вектор `y`.
- Разделите данные на обучающую и тестовую выборки со стратификацией (`train_test_split(..., stratify=y)`).

**Шаг 4. Построение pipeline**

- Используйте `ColumnTransformer` для раздельной обработки числовых (`StandardScaler`)
  и категориальных (`OneHotEncoder`) признаков.
- Оберните препроцессор и модель в `sklearn.pipeline.Pipeline`.

**Шаг 5. Обучение и сравнение моделей**

- Обучите бейзлайн (`DummyClassifier`).
- Обучите три модели с кросс-валидацией (рекомендуется `StratifiedKFold`, 5 фолдов).
- Зафиксируйте для каждой модели: Accuracy и F1-macro на кросс-валидации и на тесте.

**Шаг 6. Оптимизация**

- Выберите лучшую модель по тестовой метрике.
- Подберите для неё гиперпараметры с помощью Optuna (минимум 20 trials).
- Переобучите финальную модель с лучшими параметрами.

**Шаг 7. Логирование в MLflow**

- Настройте эксперимент: `mlflow.set_experiment("coffee_sales_classification")`.
- Залогируйте отдельными run'ами:
  - бейзлайн;
  - каждую модель из сравнения;
  - финальную оптимизированную модель.
- Для каждого run'а сохраните: название модели, параметры, CV-метрики, тестовые метрики.

**Шаг 8. Сравнение результатов**

- В терминале выполните `mlflow ui`.
- В интерфейсе сравните эксперименты по метрикам.
- Сделайте скриншот и вставьте его в ноутбук или отдельный файл.
- Напишите текстовый вывод: какая модель оказалась лучшей и почему.

**Шаг 9. (Опционально) Airflow DAG**

- Создайте файл `coffee_ml_pipeline_dag.py` с DAG из трёх задач:
  загрузка данных, feature engineering, обучение + логирование.
- Укажите расписание `@weekly`.

## Критерии оценки

**«Зачёт»**

- Выполнен первичный анализ данных и описаны выводы.
- Построен полноценный pipeline с `ColumnTransformer` и `Pipeline`.
- Обучен бейзлайн и минимум три модели, проведено их сравнение.
- Для лучшей модели выполнен подбор гиперпараметров.
- Все эксперименты залогированы в MLflow (видно минимум 5 run'ов: бейзлайн + 3 модели + финальная).
- Предоставлен скриншот MLflow UI со сравнением метрик.
- Написаны обоснованные выводы о качестве моделей.

**«На доработку»**

- Отсутствует логирование в MLflow или менее 5 run'ов.
- Не выполнено сравнение моделей (только одна модель).
- Отсутствуют выводы или скриншот MLflow.
- Pipeline собран некорректно (например, утечка данных из тестовой выборки).

**«Незачёт»** — в крайнем случае, если присылается пустое или недоработанное задание
во второй раз после отправки работы на доработку.
